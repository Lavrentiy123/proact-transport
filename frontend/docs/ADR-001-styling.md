# ADR-001. Способ стилизации frontend

- **Статус:** принято, 27.09.2026 (этап 2 переработки интерфейса).
- **Основание:** аудит интерфейса 27.09 — дизайн-токенов нет, Tailwind конфликтует с собственными стилями.

## Контекст

В `package.json` были подключены `tailwindcss` и `@tailwindcss/vite`, в `styles.css` — `@import "tailwindcss"`. При этом:

- **утилиты не используются.** В разметке нет ни одного утилитарного класса Tailwind: все стили — собственные классы компонентов в `styles.css`. Tailwind добавлял в бандл только preflight и несколько классов, совпавших по имени со словами в исходниках (`.block`, `.grid`, `.hidden`, `.table`, `.visible`), и второй `.sr-only`;
- **каскад конфликтует.** Tailwind 4 кладёт preflight и утилиты в `@layer base` и `@layer utilities`, а наши стили написаны вне слоёв. Стили вне слоёв всегда сильнее слоёв, поэтому утилиту нельзя было бы применить поверх класса компонента: `class="empty-panel hidden"` не скрыл бы элемент, потому что `.empty-panel { display: flex }` вне слоя сильнее. Две системы не складываются, а тихо перекрывают друг друга;
- **тема не связана.** Токенов Tailwind (`@theme`) нет, цвета — 185 литералов в `styles.css` (по аудиту интерфейса).

## Решение

Удалить Tailwind:

- пакеты `tailwindcss` и `@tailwindcss/vite` — из `package.json` и `package-lock.json`;
- плагин — из `vite.config.ts`;
- `@import "tailwindcss"` — из `styles.css`.

Стили пишутся обычным CSS:

| Файл | Что в нём |
|---|---|
| `src/styles/tokens.css` | единственное место с цветами и шкалами: цвет, кегли, веса, межстрочные, радиусы, тень, отступы, z-index |
| `src/styles/base.css` | сброс (то немногое из preflight, на что опиралась вёрстка), типографика по умолчанию, фокус, `.sr-only`, табличные цифры |
| `src/styles/ui.css` | примитивы из `src/ui/` (`ui-*`) |
| `src/styles.css` | раскладка и классы экранов; только `var(--…)`, без литералов цвета |

Правила:

1. Цвет, кегль, вес, радиус, отступ, тень и z-index берутся только из `var(--…)`. Hex допустим только в `tokens.css`.
2. TSX не содержит hex. MapLibre читает токены через `cssToken()` из `src/theme/tokens.ts`, SVG — через классы или `var(--…)`.
3. Подписи, иконки, формы и цвета риска — только из `src/theme/risk.ts`.
4. Новые элементы интерфейса собираются из примитивов `src/ui/`. Витрина всех состояний — `/?ui=1` в dev-сборке.

## Последствия

- **Плюсы:** одна система стилей и один каскад; CSS-бандл меньше (без preflight и случайных классов); тему можно заменить, переопределив токены в `:root`.
- **Минусы:** нет утилит для быстрой вёрстки. Отступы и кегли берутся из токенов вручную.
- **Сброс.** Preflight обнулял поля, рамки и стили заголовков. Нужная часть перенесена в `base.css`, иначе элементы сдвинулись бы.
- **Проверка.** В собранном CSS нет `.block .grid .hidden .table .visible`, а `.sr-only` объявлен один раз.

## Шрифты

- **Inter** (400, 500, 600) — интерфейс. **JetBrains Mono** (400, 500) — моно-метки статусов и времени.
- Подключены через `@fontsource/inter` и `@fontsource/jetbrains-mono`, только подмножества `latin` и `cyrillic`, в `src/main.tsx`. Файлы woff2 попадают в сборку. Внешних запросов к CDN нет.
- **Лицензия** обоих шрифтов — SIL Open Font License 1.1 (`OFL-1.1` в `package.json` пакетов 5.3.0). Разрешает использование, встраивание и распространение вместе с приложением. Сами шрифты нельзя продавать отдельно.
- Цифры в числовых элементах — `font-variant-numeric: tabular-nums` (`base.css`).

## Альтернатива (отклонена)

Оставить Tailwind: перенести собственные стили в `@layer components`, объявить тему через `@theme` из тех же токенов и постепенно перейти на утилиты.

Почему отклонена:

- разметку всех компонентов пришлось бы переписать дважды: на утилиты сейчас и ещё раз при переработке UI на этапе 3;
- в команде нет договорённостей о классах;
- выигрыш — только скорость вёрстки, а в бандл вернулся бы preflight.

Вернуться к Tailwind можно позже без потерь: токены уже вынесены в CSS-переменные, и `@theme` может ссылаться на них.
