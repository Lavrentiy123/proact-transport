# Сценарий показа frontend (около 2 минут)

## Подготовка

1. Запустить `npm ci` и `npm run dev` из `frontend/`, открыть `http://localhost:5173/?source=demo` (без параметра открывается живой поток).
2. В шапке выбрать **Демо-сценарий → Обычный поток**, нажать **Начать заново** и сразу **Пауза**. Окно 1440×900 или 1366×768, масштаб браузера 100%: весь экран — шапка, лента, карта, карточка и диаграмма — помещается без прокрутки.
3. Убедиться, что видны три борта, один красный риск (треугольник на карте), карточка с рекомендацией и диаграмма. Демо не требует backend; географическая подложка загружается из сети, а при её недоступности появляется схема маршрута.

## Реплики и действия

| Время | Действие | Что сказать |
|---|---|---|
| 0:00–0:20 | Показать общий экран: пилюля REPLAY, счётчики в шапке, лента слева, карта, карточка справа. | «Это экран диспетчера: борта, предупреждения и прогноз прибытия на 10–15 минут вперёд — на одном экране, без переключений». |
| 0:20–0:45 | Указать на красное предупреждение и карточку: полоса риска, участок, «План 12:52 · прибытие ≈ 12:58», рекомендация, причина. | «Для этого борта прогноз +6 минут 12 секунд. Видны участок, вероятный диапазон, причина затора и рекомендация». |
| 0:45–1:05 | Нажать **Отправить водителю**: появляется «Отправлено водителю» и ответ водителя. Показать диаграмму внизу: план, наблюдение, прогноз. | «Решение — в один клик, ответ водителя виден сразу. Диаграмма показывает, где наблюдение расходится с планом и куда попадает прогноз». |
| 1:05–1:25 | Нажать **Продолжить**. Через ~9 секунд при скорости ×5 появится второе предупреждение. Нажать **Пауза**, выбрать борт 122658 в ленте или в списке «Борт» над картой. | «Предупреждение поступает во время воспроизведения; выбор одновременно меняет карту, карточку и диаграмму». |
| 1:25–1:45 | Кратко показать сценарии **Нет данных** и **Потеря связи**: красная пилюля «НЕТ СВЯЗИ», баннер, «не обновляется с 12:40:00», кнопки отправки отключены. Вернуть **Обычный поток**. | «При пустом потоке и обрыве связи экран показывает явное состояние и не даёт отправить команду по устаревшим данным». |
| 1:45–2:00 | Закончить на обычном потоке и карте. | «Демо работает самостоятельно. Для реального потока frontend подключается к WebSocket и REST backend». |

## Для записи экрана

- Снять общий план и крупно карточку риска, отправку водителю, появление второго предупреждения и диаграмму.
- Скрыть посторонние окна и уведомления. Оставить читаемыми названия, время и легенду форм риска (▲ критично, ◆ внимание, ● в графике, ○ нет прогноза).
- Тестовый источник `npm run dev:stub` годится для проверки подключения, но в записи его следует явно назвать тестовым. Настоящий поток поднимается из корня репозитория командой `docker compose up --build -d` и открывается на `http://localhost:3000`.
- Не утверждать, что демонстрационный маршрут взят из реальных треков или что интерфейс доказывает точность модели. Маршрут синтетический, прогноз взят из контрактного примера; ответ водителя в демо эмулируется.

## Быстрый контроль перед показом

- `npm run typecheck`, `npm run test:contracts`, `npm run test:unit` и `npm run build` проходят.
- На 1440×900 и 1366×768 страница не прокручивается; видны карта, лента, карточка с кнопкой «Отправить водителю» и диаграмма.
- Карта показывает маршрут и маркер; при выборе второго борта они перестраиваются.
- После **Начать заново** в шапке «1 предупреждение»; при воспроизведении становится 2.
- Пауза останавливает часы, **Начать заново** возвращает 12:40:00.
- В режиме **Нет данных** нет старой карточки; в **Потере связи** красная пилюля, метка «не обновляется» и отключённые кнопки отправки.
