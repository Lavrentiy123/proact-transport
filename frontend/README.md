# ПроАкт.Транспорт — frontend

React + TypeScript диспетчерская для прогнозов отклонений транспорта. Демо-сценарий работает без backend. Картографическая подложка загружается из OpenFreeMap; если сеть или сервис недоступны, остаётся схема маршрута без подложки.

## Локальный запуск

Требуется Node.js 24 и npm.

```bash
cd frontend
npm ci
npm run dev
```

Открыть `http://localhost:5173`. Проверки: `npm run typecheck`, `npm run test:contracts` и `npm run build`. Контрактный smoke проверяет повреждённые и частичные кадры, порядок времени, отсечение будущих точек маршрута и форматирование задержки. Тот же набор запускается в [CI](../.github/workflows/frontend.yml).

## Управление демо

- **Источник → Демо-сценарий**: контрактный снимок и синтетические маршруты. `×5` означает 5 секунд модельного времени за 1 секунду просмотра.
- **Пауза / Продолжить** останавливает и возобновляет шкалу; **Начать заново** возвращает её к 12:40:00.
- Через 45 модельных секунд появляется второе предупреждение. Борта перемещаются по синтетическому маршруту.
- Сценарии **Пик алертов**, **Нет данных**, **Потеря связи** проверяют крайние состояния.
- Нажмите на предупреждение или маркер борта, чтобы сменить маршрут, карточку и диаграмму. Поиск и фильтры ленты не меняют общий счётчик алертов; кнопка «Показать все» открывает события после седьмого.
- Карта сначала показывает все борта текущего снимка. Кнопка **К маршруту** приближает выбранный маршрут; **Все борта** возвращает обзор.

## Живой поток

Переключите источник на **Живой поток**. Frontend подключается к `WS /ws/live` и запрашивает выбранный маршрут через `GET /api/v1/tracks/{tr_id}`. При обрыве WebSocket повторяет подключение с паузой 1–10 секунд, оставляя последний снимок с предупреждением об устаревании. До первого снимка видно ожидание данных; раздел «Диагностика» показывает состояние WS, время последнего снимка и возраст пакета. Некорректные кадры игнорируются.

Vite в разработке проксирует `/api` и `/ws` на `localhost:8000`. В контейнере nginx проксирует те же пути на `backend:8000` и слушает порт **3000** по `contracts/README.md`.

Для локальной проверки живого режима без команды backend во втором терминале запустите `npm run dev:stub`. Это тестовый WebSocket/REST поток на порту 8000; не запускайте его одновременно с настоящим backend.

Для нагрузочной проверки stub принимает переменные `STUB_VEHICLES=0|1|3|100|500|1000` и `STUB_ALERTS=0..1000`. Например, в PowerShell перед `npm run dev:stub`:

```powershell
$env:STUB_VEHICLES = '500'
$env:STUB_ALERTS = '50'
npm run dev:stub
```

Такие борта синтетические; каждая 20-я позиция при 100+ бортах специально имеет недопустимую широту для проверки счётчиков.

```bash
docker build -t proact-frontend ./frontend
docker run --rm -p 3000:3000 proact-frontend
```

В контейнере демо работает и без backend. Для живого потока контейнер должен находиться в сети, где доступно имя `backend`.

## Данные и ограничения

Для географической карты нужен доступ браузера к `tiles.openfreemap.org`. Подложка использует тёмный стиль OpenFreeMap и данные OpenStreetMap; атрибуция отображается на карте. URL стиля задаётся через `VITE_MAP_STYLE_URL` (пример в [.env.example](.env.example)). Значение `offline` включает локальную резервную **схему без географической подложки и тайлов**; это не полноценная офлайн-карта. При недоступности стиля интерфейс переключается на эту схему. Ошибка отдельного тайла или шрифта не должна скрывать всю карту.

Демо-снимок содержит три борта из контрактного примера, а не весь транспорт Москвы. В режиме «Живой поток» frontend учитывает все борта, которые сервер передаёт в `vehicles` сообщения WebSocket; карта показывает только записи с допустимой позицией и отдельно объясняет разницу. Для плотного снимка близкие маркеры группируются, выбранный борт остаётся доступным отдельно. Если backend недоступен или передаёт неполный снимок, frontend не может восстановить отсутствующие борта из демо-данных. При отсутствии WebGL остаются список бортов, предупреждения и карточка.

Базовые формы данных следуют `contracts/schemas.py`, а исходный снимок скопирован из `contracts/examples/ws_snapshot.json`. TypeScript-валидатор дополнительно отвергает дубли `tr_id`/`alert_id`, вероятность вне 0–1, нарушенный порядок q10–q90 и нечисловые обязательные координаты, чтобы не показывать противоречивый кадр. Числовая широта вне географического диапазона остаётся в числе полученных бортов, но не создаёт маркер: Python-контракт не ограничивает её диапазон. Время сравнивается с точностью до микросекунд в московском локальном формате без таймзоны. Плановые остановки и треки для демо созданы специально для интерфейса: ID и времена исходного снимка расходятся с опубликованным расписанием. Времена фактических прибытий из train/test/validate не используются; наблюдения и факты позднее момента снимка `T` отсекаются при отображении маршрута.

Диаграмма показывает план, наблюдения и q10–q90 для выбранного борта или события. Расстояние наблюдения вычисляется проекцией координат на отрезки маршрута. Реальное качество прогнозов здесь не оценивается. Рекомендация на карточке означает, что она показана диспетчеру, а не отправлена водителю: настоящий `POST /api/v1/actions` и история решений требуют backend. Полный end-to-end с backend требует его доступного сервиса и совместимых ответов.
