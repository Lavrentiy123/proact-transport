# ПроАкт.Транспорт — frontend

React + TypeScript диспетчерская для прогнозов отклонений транспорта. По умолчанию открывается автономный демо-сценарий без backend и картографических тайлов.

## Локальный запуск

Требуется Node.js 24 и npm.

```bash
cd frontend
npm ci
npm run dev
```

Открыть `http://localhost:5173`. Проверки: `npm run typecheck` и `npm run build`.

## Управление демо

- **Источник → Демо-сценарий**: контрактный снимок и синтетические маршруты. `×5` означает 5 секунд модельного времени за 1 секунду просмотра.
- **Пауза / Продолжить** останавливает и возобновляет шкалу; **Начать заново** возвращает её к 12:40:00.
- Через 45 модельных секунд появляется второе предупреждение. Борта перемещаются по синтетическому маршруту.
- Сценарии **Пик алертов**, **Нет данных**, **Потеря связи** проверяют крайние состояния.
- Нажмите на предупреждение или маркер борта, чтобы сменить маршрут, карточку и диаграмму.

## Живой поток

Переключите источник на **Живой поток**. Frontend подключается к `WS /ws/live` и запрашивает выбранный маршрут через `GET /api/v1/tracks/{tr_id}`. При обрыве WebSocket повторяет подключение с паузой 1–10 секунд, оставляя последний снимок с предупреждением об устаревании. Некорректные кадры игнорируются.

Vite в разработке проксирует `/api` и `/ws` на `localhost:8000`. В контейнере nginx проксирует те же пути на `backend:8000` и слушает порт **3000** по `contracts/README.md`.

Для локальной проверки живого режима без команды backend во втором терминале запустите `npm run dev:stub`. Это тестовый WebSocket/REST поток на порту 8000; не запускайте его одновременно с настоящим backend.

```bash
docker build -t proact-frontend ./frontend
docker run --rm -p 3000:3000 proact-frontend
```

В контейнере демо работает и без backend. Для живого потока контейнер должен находиться в сети, где доступно имя `backend`.

## Данные и ограничения

Типы соответствуют `contracts/schemas.py`, а исходный снимок скопирован из `contracts/examples/ws_snapshot.json`. Плановые остановки и треки для него созданы специально для интерфейса: ID и времена исходного снимка расходятся с опубликованным расписанием. Времена фактических прибытий из train/test/validate не использованы.

Диаграмма показывает план, наблюдения и q10–q90 для выбранного борта. Расстояние наблюдения вычисляется проекцией координат на отрезки демонстрационного маршрута. Реальное качество прогнозов здесь не оценивается. Полный end-to-end с backend требует его доступного сервиса и совместимых ответов.
