## 2. Логика решения

```
NDTP-поток (эмулятор или наш replay исторического дня)
   │ TCP :9201
   ▼
backend ── парсер NDTP → состояние бортов (буфер 30 мин) → детектор прибытий на остановки
   │          (сверка с расписанием: текущее отклонение, скорость на перегоне, простой)
   │ каждые 5 с: для каждого борта остановка в окне 10–15 мин → признаки → один батч
   ▼
ml-core ── CatBoost (+ малая PyTorch-модель) → задержка, интервал q10–q90, P(опоздание), причина
   ▼
backend ── риск (зелёный/жёлтый/красный) → алерт → рекомендация (скорость / межрейсовая стоянка / резерв)
   │ WebSocket 1 Гц
   ▼
frontend ── карта, лента алертов, карточка инцидента, «отправить водителю», Марей, What-If
```

Главные решения:
- **Основной источник демо — наш replay** реального дня (06.01.2026) через бинарный NDTP на свой же сервер. Так прогнозы осмысленные. Официальный эмулятор подключаем для доказательства совместимости и нагрузочного теста (его `autoGenerate` — случайное блуждание, прогнозировать там нечего).
- **Признаки считает один общий пакет `features/`** и при обучении, и на потоке. Иначе метрики на потоке разойдутся с офлайн-метриками.
- **На потоке нет подсказки `cur_dev_s`**, её восстанавливает детектор прибытий. Для потока обучаем модель на восстановленном отклонении, для сабмита — на официальном.
- **Рекомендации по правилам**, а не ML: опаздывает → средняя скорость, которую надо держать; опережает → межрейсовая стоянка; красный риск на первом или последнем рейсе → резерв. Опоздания на первом и последнем рейсе поднимаем в приоритете: для перевозчика это прямые деньги (QA-сессия, 34:08).
- **«Отправить водителю»** — канал NDTP «диспетчер ↔ водитель», в демо эмулируем ответ («успеваю / не успеваю / нештатная ситуация»).

**Приоритеты:**
- **P0, к 22:00 26.09** — сквозной поток работает: сабмит ≥ 0.70, NDTP-сервер и replay, тик → ml-core → алерты, WebSocket, карта с цветом бортов, лента алертов и карточка, `docker compose up`.
- **P1, к 14:00 27.09** — причина с доказательством, рекомендации и «отправить водителю», метрики горизонта, режим DEGRADED, эмулятор и нагрузочный тест, диаграмма Марея, PyTorch в ансамбле, pdoc и README.
- **P2, если останется время** — What-If (стоянка, резерв), риск «паровозика» на демо-парах train-дня, режим «Сеть», AI-помощник на российской модели.
- **Не делаем:** мобильное приложение, авторизацию, офлайн-тайлы, глубокую симуляцию выпуска резерва.

4. Верхняя плашка: режим LIVE/DEGRADED/REPLAY, время симуляции, скорость replay, число алертов.
