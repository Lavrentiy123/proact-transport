# Анти-утечка: правила, находки и тесты

Модель прогнозирует задержку прибытия на остановку через 10–15 минут. Утечка здесь — любое использование
того, чего в момент прогноза `T` ещё нет: будущей телеметрии, фактов прибытия, меток других точек.
Ниже — правила, которых мы придерживаемся, что мы нашли в данных и какие тесты это проверяют.

## 1. Правила

1. Признаки для точки `(tr_id, T)` строятся только из телеметрии с `event_time ≤ T` и из **планового**
   расписания. Телеметрия дополнительно ограничена окном `(T − 30 мин, T]` — ровно столько держит буфер на потоке.
2. Факт прибытия (`time_fact_begin`) запрещён в любом виде в `features/`, `ml_core/`, `src/ml/` и в инференсе.
   Он используется только как target (через `labels`) и для оценки детектора и онлайн-MAE (`tests/`, `src/eval/`).
   Пакет `features` при чтении расписания даже не загружает эту колонку.
3. `tr_id` и `unit_id` не являются признаками. Телеметрия синтетической копии не используется как признак
   другого борта: у каждой точки — только её собственный трек.
4. Нет early stopping и подбора гиперпараметров по test или validate. Число итераций CatBoost, база остатка
   онлайн-модели и вес PyTorch-члена в бленде выбираются только по LOBO.
5. Метки других точек — не признаки; target encoding по всему дню не используется.
6. Пропуски — `NaN` (CatBoost обрабатывает их сам); `fillna(0)` не используется, чтобы онлайн и офлайн видели одно и то же.
7. Прибытие, обнаруженное детектором «задним числом» (проезд мимо остановки определяется по следующему фиксу),
   считается известным с момента **обнаружения** `t_det`, а не с момента проезда `t_arr`.

## 2. Что нашли в данных и почему не использовали

| Находка | Почему это утечка | Что сделали |
|---|---|---|
| **validate = тот же период, что test.** Факты для 100 % целевых остановок validate лежат в `train/schedule.csv` и `test/schedule.csv`; `validate/traffic.csv` байт-в-байт совпадает с `test/traffic.csv` | Сабмит по фактам дал бы почти нулевой MAE, но это подсмотр ответа, а не прогноз | Удалили из `src/train.py` блок, считавший «Validate MAE» по фактам (ML-T1). Validate используется только для построения сабмита по плану (`schedule_plan.csv`) и телеметрии до `T` |
| **Синтетические борта** `9000000+2i`, `9000001+2i` — копии i-го реального борта со сдвигом по времени (подтверждено: совпадение набора координат остановок 26/26, корреляция профиля `cur_dev_s` 0.93/0.92/0.91 на первых трёх парах) | Копия отложенного борта в обучении — почти тот же борт; оценка по «чужим» бортам была бы завышена | Группа LOBO = реальный борт + обе его копии (`src/ml/cv.py`, `bus_of`) |
| **Один день.** train, test и validate — 06.01.2026, те же 13 реальных бортов | Official split (train → test) — это «тот же день, те же борта» и переоценивает качество | Показываем три оценки: official (для сравнения с LB), LOBO по бортам (основная, по ней выбираем модели) и сдвиг во времени FWD |
| **Early stopping по test** в исходном `src/train.py` (`eval_set=(X_test, y_test)`) | Число деревьев подобрано по тесту | Убрали; параметры фиксированы, итерации выбираются по LOBO (ML-T1, ML-T3) |
| **Официальная подсказка `cur_dev_s` не причинна.** На train она на 96 % (MAE 0.8 с) равна факту на последней остановке с **плановым** временем ≤ T — даже когда борт доехал до неё уже после T | Подсказка организаторов содержит кусочек будущего. Для сабмита её использовать разрешено (она есть в `validate/points.csv` и в README датасета), но на потоке её нет | Модель сабмита `m_ds` использует официальную подсказку; модели потока обучены на **восстановленном** детектором отклонении и честно хуже (LOBO 79.5 с против 75.2 с). Сравнение не смешиваем |

## 3. Какие тесты это проверяют

| Тест | Что проверяет |
|---|---|
| `tests/ml/test_no_leakage_static.py` | В `src/train.py`, `features/`, `ml_core/`, `src/ml/` нет подстрок `time_fact_begin` и `eval_set=(X_test` |
| `tests/ml/test_features.py::test_no_leakage_future_track_is_ignored` | Признаки по полному треку == по треку, обрезанному на `T` == по треку с мусором после `T` (50 точек test) |
| `tests/ml/test_features.py::test_batch_equals_single` | Батч для обучения считает то же, что поштучный расчёт (1e-9) |
| `tests/ml/test_online_parity.py` | `OnlineVehicle` на потоке даёт те же признаки, что офлайн-батч (2 борта test, 1e-6), в том числе при пакетах не по порядку |
| `tests/ml/test_stop_detector.py::test_known_uses_detection_time` | Проезд мимо остановки не «известен» до момента его обнаружения |
| `tests/ml/test_models.py::test_lobo_no_leakage` | Ни одна точка отложенного борта и его копий не попадает в обучение фолда |
| `tests/ml/test_validate_submission.py` | Формат сабмита (151 строка, `sample_id` как в `points.csv`, `;`, без BOM) |

Факты прибытия читают только: `tests/ml/test_stop_detector.py` (точность детектора на train) и
`src/eval/online_replay_eval.py` (онлайн-MAE). Оба — оценка, а не признаки.
