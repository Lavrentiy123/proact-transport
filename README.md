## 📋 Официальное описание трека от организаторов

> **«Точное соблюдение графика движения — главная метрика качества наземного пассажирского транспорта.**  
> Разработайте ИИ-систему для раннего прогнозирования изменений в движении транспорта (за 10-15 минут до ее фактического наступления задержки).  
> Система должна непрерывно анализировать потоковые телематические данные (**формат NDTP**), сопоставлять их с эталонным расписанием, выявлять паттерны сбоев и визуализировать проблемные участки на дашборде диспетчера. Это позволит операторам переходить от реактивного управления (когда транспорт уже опоздал) к проактивному — принимать упреждающие меры.»

### Ключевые функции будущего решения по ТЗ:
1. **Анализ потоковых данных:** обработка исторических и real-time телематических данных (протокол **NDTP**) и сопоставление их с расписанием.
2. **Раннее детектирование:** выявление транспортных средств с высокой вероятностью задержки в ближайшие 10–15 минут.
3. **Диспетчерский BI-дашборд:** информативный интерфейс с визуализацией уровня риска на маршрутах.

### Рекомендованный состав команды (5 человек):
* **2 ML Engineers:** построение и обучение предиктора на исторических данных телематики (CatBoost / LightGBM, нейросети).
* **1 Backend-разработчик:** Python / FastAPI, высоконагруженная интеграция моделей, оборачивание предикта в web-сервис.
* **1 BI-аналитик или Frontend-разработчик:** создание интерактивного дашборда для диспетчера (React, MapLibre GL).
* **1 Аналитик данных / DBA:** потоковая телематика NDTP, PostgreSQL, привязка к расписанию и расчет метрик.

## 💡 Концепция решения: «ПроАкт.Транспорт»

### Суть решения
**«ПроАкт.Транспорт»** — интеллектуальный помощник линейного диспетчера, который за **10–15 минут** предупреждает о риске сбоя интервала («каравана» автобусов / bus bunching) и предлагает готовое действие: скорректировать время стоянки сзади идущего транспорта (**Dynamic Holding**), сохранив равномерность движения.

### Как устроена система (4 ключевых блока):
1. **Первичная обработка телематики:**
   * Парсинг потоковых данных координат (**NDTP / Parquet / CSV**) и привязка к остановкам маршрута (Map Matching);
   * Фильтрация сбоев GNSS (отсечение резких скачков координат, аномальных скоростей и дрейфа на конечных).
2. **ML-ядро на CatBoost:**
   * Прогнозирование времени прохождения перегонов и стоянок на 10–15 минут вперед;
   * Модель опирается на интерпретируемые признаки: текущее отставание, дистанция до впереди идущего борта, скорость потока на участке, час пик и скользящая статистика сегмента.
3. **Модуль подсказок диспетчеру (СППР):**
   * Расчет времени упреждающего удержания (**Dynamic Holding**) на узловой остановке (40–80 секунд), чтобы задний автобус не «догнал» передний;
   * Оценка сэкономленного времени пассажиров (**EWT — Excess Wait Time**).
4. **Диспетчерский интерфейс (BI-дашборд):**
   * Карта движения маршрута в реальном времени с цветовой индикацией рисков (зеленый / желтый / красный);
   * Диаграмма исполненного движения (Time-Space Diagram / график Марея);
   * Лента ранних предупреждений с кнопкой быстрого применения решения («Выдать команду на удержание интервала»).

### Стек технологий:
`Python (FastAPI)` • `CatBoost` • `Scikit-learn` • `PostgreSQL` • `React` • `MapLibre GL` • `Docker`

### Польза для города и пассажиров:
* **Устранение эффекта «паровозика»** (когда сначала долго нет автобуса, а потом приходят два разом);
* **Снижение среднего времени ожидания (EWT)** пассажиров на остановках;
* **Снижение стресса диспетчера:** система сама находит проблему заранее и дает готовый рецепт решения.
